# Передача проекта

Актуально на 7 октября 2026 года.

Этот документ содержит техническую информацию для продолжения работы после переустановки или передачи проекта другому администратору. Здесь намеренно нет IP-адресов, логинов, паролей, SSH-ключей, токенов и данных баз. Доступы должны храниться отдельно в защищённом хранилище.

## 1. Проект

- Название: Unix Lineage2 Control Panel.
- Автор и копирайт: Steve Dog, https://steve.dog.
- Репозиторий: `SteveDogs/Unix-Lineage2-Control-Panel`.
- Основная ветка: `main`.
- Текущая версия: `1.4.0`.
- Проверенный коммит кода: `5834bf3`.
- Язык реализации: Bash.
- Поддерживаемые языки меню: русский, английский и украинский.
- Панель управляет компонентами LOGIN, GAME и Active Anticheat.

Основные возможности:

- компактный и полный статус серверов;
- запуск, остановка и безопасный перезапуск;
- управление одной сборкой или всеми сборками;
- режим обслуживания;
- мониторинг CPU, RAM, PID, портов и времени работы;
- проверка конфликтов портов перед запуском;
- просмотр и слежение за логами;
- поддержка обычных loop-скриптов, `screen` и systemd;
- диагностика конфигурации командой `l2doctor` или её автономным аналогом.

## 2. Структура исходников

```text
bin/                 команды l2, l2ctl, l2menu, l2ps и l2doctor
lib/                 конфиги, процессы, переводы и общие функции
config/              примеры глобальных и серверных конфигов
docs/                документация на трёх языках
.github/workflows/   проверки GitHub Actions
install.sh           стандартная установка
uninstall.sh         удаление панели
```

Версия задаётся в `lib/common.sh`. Конфигурация каждого сервера хранится отдельным файлом `*.conf`; приватные конфиги не должны попадать в публичный репозиторий.

## 4. Проверка после переустановки

Локально:

```bash
git clone https://github.com/SteveDogs/Unix-Lineage2-Control-Panel.git
cd Unix-Lineage2-Control-Panel
git checkout main
git log -1 --oneline
```

Перед любыми изменениями выполнить:

```bash
bash -n bin/*
bash -n lib/*
bash -n install.sh
bash -n uninstall.sh
shellcheck -s bash bin/* lib/* install.sh uninstall.sh
shfmt -d bin/* lib/* install.sh uninstall.sh
git diff --check
```

В GitHub Actions используются ShellCheck `0.11.0` и shfmt `3.13.1`. ShellCheck настроен как рекомендательная проверка, остальные проверки обязательны.

## 5. Выкладка основной установки

1. Убедиться, что локальные проверки и GitHub Actions завершились успешно.
2. Проверить чистоту рабочей копии на VPS командой `git status --short`.
3. Сделать отдельные архивы `/etc/unix-l2-control-panel` и `/opt/unix-l2-control-panel`.
4. Выполнить только fast-forward обновление:

```bash
cd /root/Unix-Lineage2-Control-Panel
git pull --ff-only origin main
./install.sh
```

5. Не заменять боевые конфиги примерами из репозитория.
6. Сравнить PID до и после установки.
7. Выполнить:

```bash
l2ctl status
l2ctl monitor
l2ctl ports
l2doctor
```

Обычная установка не должна перезапускать игровые процессы.

## 6. Выкладка автономной установки

Автономный VPS не должен клонировать репозиторий. Пакет собирается на доверенном компьютере из проверенного коммита:

```bash
tar -czf stevedogs-l2-panel.tar.gz bin lib LICENSE
```

Порядок обновления:

1. Сделать архивы `/opt/stevedogs-l2-panel` и `/etc/stevedogs-l2-panel`.
2. Передать архив по SCP во временный файл.
3. Распаковать код в `/opt/stevedogs-l2-panel`, не заменяя каталог конфигов.
4. Проверить Bash-синтаксис.
5. Удалить переданный архив и все временные установочные каталоги.
6. Сравнить PID до и после обновления.
7. Выполнить `stevedogsctl status`, `stevedogsctl monitor`, `stevedogsctl ports` и `stevedogsdoctor`.

Локальный файл `stevedogs-l2-panel.tar.gz` исключён из Git и может быть пересобран из исходников.

## 8. Что запрещено без согласования

- Останавливать или перезапускать живые LOGIN, GAME и AA для проверки изменений.
- Завершать Java или AA по PID вручную, если компонент управляется systemd или loop-скриптом.
- Выполнять `git reset --hard`, `git clean`, принудительный push или переписывать историю.
- Заменять боевые конфиги файлами `example.conf`.
- Публиковать IP, пароли, SSH-ключи, токены, настройки баз данных и приватные серверные конфиги.
- Менять firewall, сетевые туннели, proxy-конфиги и скрипты `ipip*.sh`.
- Включать, отключать или редактировать systemd-службы без понимания текущего владельца процесса.
- Удалять игровые каталоги, логи, базы, резервные копии и Active Anticheat.
- Запускать автономную установку напрямую из непроверенного архива.
- Оставлять установочные архивы и временные файлы на VPS после успешной выкладки.

## 9. Минимальная проверка перед передачей

- Исходники находятся на ветке `main`, рабочее дерево чистое.
- Последний коммит и версия записаны в этом документе.
- GitHub Actions зелёный.
- На каждом VPS статус и диагностика завершаются без ошибок.
- Все ожидаемые порты имеют состояние `OWN`, остановленные компоненты — `FREE`.
- PID не изменились во время установки панели.
- Приватные доступы сохранены отдельно и проверены.
- На VPS нет временных установочных файлов.

## 10. Доступы

Доступы не входят в этот документ и не должны храниться в репозитории. В защищённом хранилище должны быть отдельные записи для:

- GitHub-аккаунта владельца;
- основной установки;
- автономной установки;
- proxy/VPN-узлов;
- баз данных и внешних сервисов.

Для каждой записи сохранить назначение, адрес, пользователя, способ авторизации, дату последней проверки и ответственного человека.
